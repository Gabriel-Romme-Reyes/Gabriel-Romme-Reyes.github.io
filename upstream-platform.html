BACKEND · PLATFORM ARCHITECTURE

API Access & Real-Time Data Pipeline

I built foundational services upstream of the CRM, providing the access and real-time data that the application consumes.

What I built

API gateway & authentication

Worked on the gateway and auth-service integration. The auth service uses browser automation to obtain and refresh the account credentials that support API requests and socket sessions. These services sit outside the CRM application.

WebSocket event ingestion

Normalized incoming events and implemented stable event identities to support downstream duplicate handling.

Caching & live delivery

Worked on subscribers, Redis-backed state, API retrieval, and SSE updates that make operational data available to the CRM.

Result

≥229 unique messages/min · zero dead letters

In a retained two-hour production observation, the surrounding pipeline’s two canonical writers persisted at least 27,530 unique messages, or 229.4 per minute, while the writer queue drained to zero with no dead letters. This is observed writer throughput across proactive and reactive inputs, not a theoretical maximum or WebSocket-only measurement. My gateway, browser-automated authentication, socket ingestion, caching, and SSE services form the upstream foundation consumed by the CRM.

Why this work mattered

What does the CRM need before its workflows can run?

The application depends on access to external APIs and a usable view of incoming events. My work covered those upstream responsibilities, from gateway and account authentication to ingestion, caching, and live updates.
